# 容器与网络边界案例

适用于整体容器黑盒、独立上层应用、真实网络故障和进度观察。以下是职责与证据示意，不规定容器数量、协议实现或 Docker 网络模式。

## 案例一：独立应用应跨越约定的服务边界

需求是两个常驻传输服务和一个共享云存储，由独立生产者与消费者使用。把两个应用通过 `docker exec` 启动在服务容器里，虽然 PID 不同，却复用了服务的文件系统、依赖和网络环境，不能证明独立应用部署可用。

```text
容器内调用：测试驱动 → 服务容器内的客户端进程 → 同容器服务

独立应用：测试驱动 → 独立 producer → 公开协议 → 发送服务
                                           → 接收服务 → 正式文件
                    独立 consumer ← 完成通知 → 独立读取并核验正式文件
共享依赖：两端服务分别访问同一个约定的对象存储
```

应用使用真正公开的客户端库和接口生成包。按生产契约挂载源目录或只读接收目录，并说明容器路径与宿主机/卷的映射；消费者独立核验产物，不执行服务应负责的搬运与发布。不要为每种路由重复部署同一个共享依赖。

明确常驻服务与每轮临时应用。先等消费者真正就绪再发送，记录业务终态、应用退出码和启动包装进程的状态；业务完成不等于外层进程已退出。超时定位到对应层，不根据一次包装进程问题普遍禁用某种容器命令。清理仅针对本轮拥有的容器和卷，保留证据及原有部署。

反向情形：用户只测同进程组件或容器内冒烟，不额外建立独立应用部署。共享同一镜像不必然违反独立容器边界；是否验证了独立依赖打包应另行说明。

## 案例二：选择云路由与证明直连不可达是不同场景

先列清客户端到本端服务的控制面、两端服务之间的直接传输面，以及各端到云中心的路径。场景名称或两个 Docker network 不能替代连通性证据：若两端还共享另一张网，直连可能绕行。

| 场景契约 | 应实际确认的网络条件 | 业务期望 |
|---|---|---|
| 显式使用直连 | 约定控制端口与传输端口可达，实际发现/广告地址指向该链路 | 直连成功并独立核验文件 |
| 显式使用云中转，只要求选路 | 云中心可达 | 云路由成功；不据此声称两端隔离 |
| 云中转应在两端无法直连时可用 | 相关方向的控制和传输端点被阻断，替代地址不会绕行；本端客户端和云中心仍可达 | 云传输成功 |
| 自动回退 | 直连尝试确实失败，云中心可达 | 按已实现策略回退，结果标明最终路径 |

在执行该场景的实际网络命名空间与方向探测允许/拒绝条件，保存生效规则或断网状态、连接结果和恢复证据。每个宣称“直连不可达”的场景都要有依据，不能只在回退用例注入故障，就给全部云用例作同样结论。上层 fixture 提供的 AUTO 策略也不能算作服务原生能力。

生产采用 host networking 时，说明测试映射保留了哪些语义。同一宿主机共享 host 网络栈不自动模拟两台隔离主机；选择独立网络命名空间、多主机或受控规则等合适方案。ROS 2/DDS 等发现与客户端通信可能受网卡变化影响，断链后仍要确认本端 Action 和必要通知可用，避免测到错误的故障。

反向情形：契约仅要求选择 CLOUD，允许两端互通时，无须增设防火墙；仅讨论生产设计时也不实际修改网络。

## 案例三：观察限速留在测试环境

用户想肉眼看到真实中间进度，并要求不侵入业务。为此向业务后端加限速参数或测试角色分支，会改变被验收对象；优先在隔离测试网络中整形目标流量，例如容器网络命名空间内的 `tc`，并核对规则、吞吐或持续时间确实改变。已有公开配置恰好满足观察需求且用户允许使用时，也可沿用。

```text
观察准备：选择数据量与速率 → 只限制目标传输链路 → 确认控制面仍可用
执行验收：公开请求 → 收集真实字节反馈 → 真实终态 → 核对接收产物
结束：保存证据 → 移除本轮规则或回收所属网络 → 确认恢复
```

按实际业务超时选择参数，不为制造长窗口偷偷延长产品超时。原始反馈的解析缺陷应正常修复；固定反馈、额外 sleep 或重复打印同一数值不能证明进度更准确。应用处理字节也未必等于网卡即时发送字节，按协议解释计量含义。

只改本轮测试网络，不把容器内规则命令误用到宿主机共享网卡。生产 QoS 需求按其自身契约实现；快速测试无需为展示而默认降速。仅为观察配置环境不会自动激活 TDD 审批。

## 场景回放

- 正向输入：将 ROS Action 服务作为整体黑盒，用独立应用验证直连、断直连后的云传输，并显示中间进度。检查客户端是否在服务外、故障条件是否真正成立、控制面是否保留、进度是否真实、资源是否只清理本轮。
- 邻近反例：只解释现有 HTTP 服务怎么运行，或只补一个内部函数单测。前者给明确执行位置与验收命令，不擅自部署；后者不增加 Docker、网络整形或 TDD 阶段。
- 以上定义回放任务；静态核对、场景推演与真实环境执行分别记录，不能因文档齐全就宣称运行通过。
