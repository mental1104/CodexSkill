# 人工验收与原子命令

## 先把命令放在正确环境

从用户当前终端和现有部署确定执行位置，明确宿主机、工具容器和服务容器，以及工作目录、可达地址、端口与实际工具位置。默认把操作者留在一个终端，通过显式容器命令访问目标；确需多终端时标清每个窗口及共享状态来源。

不要在容器 shell 中继续给宿主机的 Docker 命令，也不要把宿主机的 localhost 当作容器监听地址。命令使用绝对路径或先给出必要的切换目录步骤，不能默许读者已经位于仓库根目录。

提交耗时任务前先验证工具和连通性。HTTP 默认使用 curl，WebSocket 默认使用 websocat；用户另有指定时遵循其选择。缺工具时，在授权环境选择已确认架构和版本的官方二进制或现有工具容器；宿主机无法访问网桥时，工具容器是可选落点。用户指定二进制工具时，不能为省事切换成 Python 客户端。

## 让每一步可以直接粘贴

- 按业务动作给出短命令块：准备、提交、观察、查询、产物核验和清理；每块注明执行位置、目的和一个关键预期结果。原子指一个可独立观察结果的动作，不强求只有一行 shell。
- 公共初始化一次完成；其余步骤直接调用指定工具。已有脚本可以准备夹具或保留为快捷入口，但用户要求原子命令时，不能只交付脚本子命令或把整套验收藏在脚本后面。
- 从真实响应自动解析并校验任务 ID、地址、文件名、大小和摘要，保存必要状态供后续步骤读取；新终端或容器也应自动恢复。避免让人复制 ID、手改占位符或临时输入订阅 JSON。
- 提交前清空旧任务 ID；检查请求退出状态、实际 HTTP 状态码和有效响应后才继续。失败保留原始回执并停止依赖步骤，不能沿用旧值。负向场景保留错误响应正文，不能让客户端选项提前吞掉验收依据。
- 明确哪些命令会新建任务、删除产物或回收环境；查询和查看日志可以重复执行，不能以“重新观察”为名隐式再次提交业务。

## 不要错过运行窗口

工具准备应在提交前完成。需要观察实时进度时，提交后立即用本次响应中的 ID 自动订阅；按协议发送完整订阅消息，保持输入及连接可用，说明如何退出或有界等待。

实时观察应看到订阅确认、快照和实际进展；在支持重连终态快照的协议中，任务已结束时直接验收该快照，不再等待新的进度。若目标必须包括运行中观察或取消，而本次窗口已错过，应明确说明该项未验收，并在已授权范围内另起一轮。

为取消分支安排独立运行和足够耗时的真实负载，确认取消时尚未完成。不要在成功文件的删除步骤之后才让用户验证运行中取消，也不要把关闭 WebSocket 当作取消。

## 给人可复查的验收点

每一阶段同时提供协议预期、按本次完整标识过滤的日志入口和产物检查：开始要能区分受理与实际执行，过程要能看到真实推进，成功要有终态与内容核验。

长耗时流程给出合理的观察窗口和超时后的定位入口。最终保留本轮原始证据，再回收本轮临时工具、服务、文件或配置；清理范围沿用用户授权，不清除常驻服务或历史验收材料。
