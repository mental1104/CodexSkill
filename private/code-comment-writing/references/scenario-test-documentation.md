# 业务场景测试的注释与观察日志

适用于读者要把集成测试和已确认业务时序逐项对照的场景。注释可以更密集，但应减少读者推理，不是复述语法。

## 注释从术语改成动作

下面是注释对照，不是测试实现：

| 对应语句 | 信息不足的注释 | 更容易阅读的注释 |
|---|---|---|
| 创建发送端源文件 | 准备 filesystem fixture | 从端先放一个真实文件，传完后用它核对接收内容 |
| 上层客户端提交任务 | 执行 Action | 上层应用只给对端身份；地址由 FileManager 自己查 |
| 接收进度回调 | 处理 Feedback | 传完前应收到真实字节进度，不能只看到 0 和完成 |
| 检查正式目录与 staging | 验证 publish invariant | 正式文件应已出现，原临时文件应已移走 |
| 检查返回值 | 校验 Result | 上层收到的任务号、字节数和摘要必须对应这次文件 |

阶段可以按“准备环境 → 发起请求 → 观察进度 → 核对产物”分组；字段注释解释身份、路径和摘要在本次业务中的作用，不只写“这是字符串”。只在局部变量确实可以在该阶段结束时释放时增加作用域，共享状态不为分块而反复创建。

反向情形：普通循环里的赋值、自增及显而易见的辅助调用不需要逐行解释；复杂协议字段的准确约束也不能为了白话而删掉。

## 观察日志沿实际事件输出

用户需要像阅读时序图一样观察测试时，在真实回调或已完成的动作处记录方向、阶段与相对耗时，关联本次任务。调用前只能写“开始请求”，收到受理回执后才写“已受理”；没有观察到发现或发布结果，就不能预先打印“发现完成”“发布成功”。

默认运行时输出仍用 ASCII 英文。用户明确要求中文测试观察日志时，可以采用下述表达；标识和数据字段保留原形：

```text
[case=receive][task_id=task-a][+12 ms] 上层应用：已收到任务受理回执
[case=receive][task_id=task-a][+950 ms] 传输进度：bytes=65536 total=262144
[case=receive][task_id=task-a][+4200 ms] 上层应用：已收到成功 Result
```

这只是日志样式示例，不能作为测试通过证据。生产日志、错误码和协议字段继续遵循各自约定，不因一次测试中文化一起改语言；进度记录也应适当节流，保持主流程可读。

## 调用方视角的证据输出

仅打印“提交 Goal”“收到结果”“测试通过”，仍需要读源码才知道传了什么、文件在哪里。改进后按同一次调用展示以下信息：

| 阶段 | 日志让读者能复核什么 |
|---|---|
| 准备输入 | 调用方真实源文件的绝对路径、存在状态、大小和摘要 |
| 提交请求 | 实际发送的完整请求对象，包含对端身份、方向、路径和路由等已有字段；不得根据期望值事后拼造 |
| 执行反馈 | 本次任务的受理状态、实际反馈字节和总量、阶段及时间；不同流用明确文本标签关联 |
| 返回结果 | 调用方真正收到的成功/失败、错误码、任务标识、大小、摘要和发布位置等已有字段 |
| 独立核验 | 接收端正式文件与 staging 的实际状态，重新读取的内容摘要与请求、响应之间的对应关系 |

请求和响应按真实结构缩进输出，而不是将所有字段压成一行。下例只示意排版，字段须换成项目既有协议，不新增接口契约：

```json
{
  "peer_id": "peer-b",
  "source_namespace": "outbound",
  "source_path": "report.bin",
  "destination_namespace": "received",
  "destination_path": "report.bin"
}
```

验收输出复用实际断言读取的值，保留失败时的观测；不能因为某条路线通过，就只展示它而省略同轮另一条失败路线。若测试会自动删除临时目录，应在清理前完成独立核验并保留证据，说明日志中的临时路径随后可能已不存在。

颜色可区分路线、进度及成功/失败；终端自动启用或沿用仓库显式开关，重定向和归档保留可读纯文本。颜色不能成为识别不同流或判断结果的唯一依据，也不要求测试断言 ANSI 控制符。

## 发现与建连的诊断

需要解释“根据设备身份如何找到对端”时，在真实解析、缓存命中/失效和连接完成处记录：查询身份、发现来源、实际 IP/端口、连接目标及结果。只打印“开始发现”或使用本地监听配置值，不能说明实际解析到了谁。

用户允许补生产 DEBUG 时，继续使用英文和仓库已有日志设施，例如下述格式示意；测试观察层可按要求用中文串起同一身份和任务：

```text
event=peer_resolved peer_id=peer-b source=discovery cache=miss address=127.0.0.1 port=41000
event=control_connected peer_id=peer-b address=127.0.0.1 port=41000
```

这些是格式示例，不是已发生事件。已有足够日志时复用；用户只要阅读说明时不擅自添加生产埋点，简单测试也不强制打印与当前验收无关的全部字段。
